## 3. 详细记录

### 3.1 选题与方案比较

**我的提示词（摘要）：**

> 这是人工智能课程的作业，需要做一个可运行的、上传到 GitHub 上面的作品，你有什么建议吗？

**AI 输出摘要：**

AI 先识别附件中的提交要求，指出网页项目必须部署到 GitHub Pages、代码类作品需要运行说明、AI 交互记录需要体现迭代过程。随后给出若干方案，包括神经网络实验台、手写数字识别、手势控制小游戏、图片分类等。

**我的决策：**

选择“神经网络实验台”。原因是：

1. 不需要后端和 API Key，适合 GitHub Pages。
2. 能展示人工智能基础，而不是简单调用接口。
3. 可视化效果强，适合演示视频。
4. 三周内可以做出完整版本。

### 3.2 非专业用户与代码来源

**我的提示词（摘要）：**

> 我需要一个非机器学习专业人士也能用的网站，如果核心代码让别人手写的话，是不是不太行？

**AI 输出摘要：**

AI 区分了“网站是否易用”和“代码由谁完成”两个问题，并建议：

- 对普通用户隐藏学习率、网络深度等参数；
- 提供一键演示和预设模型；
- 保留手写小型网络作为教学亮点；
- AI 可以辅助生成代码，但作者必须能够解释核心流程，并如实记录 AI 使用过程。

**我的决策：**

保留从零实现的 MLP，同时增加“一键演示”入口。最终页面将学习率和训练轮数放在“进阶参数”中，默认不展开。

### 3.3 技术路线选择

**环境检查结果：**

- 本机 PATH 中没有 Node.js 和 Git。
- Python 3.7 可用。
- 课程要求部署到 GitHub Pages。

**AI 建议：**

使用原生 HTML/CSS/JavaScript，不引入构建工具和第三方机器学习库。这样：

- 本地只需要 Python 静态服务器；
- GitHub Pages 直接托管根目录即可；
- 不需要 `npm install`；
- 不会因为 CDN 或模型下载失败导致演示中断。

**我的决策：**

接受该方案。项目采用 ES Module 组织代码，通过 `python -m http.server 8000` 运行。

### 3.4 核心算法实现

AI 生成并解释了以下模块：

- `js/random.js`：可复现随机数、高斯噪声、洗牌。
- `js/data.js`：双月牙、同心圆、螺旋、XOR 数据生成。
- `js/network.js`：`MLP` 类，包含前向传播、softmax、交叉熵、反向传播和 Adam。
- `js/charts.js`：Canvas 绘制损失和准确率曲线。
- `js/main.js`：训练循环、状态管理、事件绑定、决策边界渲染和导出。

我在运行前检查了模块导入、DOM id 和语法，并通过本地浏览器验证页面能够加载。

### 3.5 数据集问题与修正

**发现问题：**

第一次训练测试中，线性分类器在“双月牙”上也能达到 92.1%，随机初始化模型甚至可能直接达到 100%。继续检查后发现，最初生成的月牙数据在纵向上几乎完全分开，导致任务过于简单。

**AI 修正：**

把双月牙改为交错的上下半圆弧，两个类别在空间上互相穿插。重新测试后：

| 模型 | 双月牙测试准确率 |
| --- | ---: |
| 线性分类器 | 92.1% |
| 小型 MLP | 100% |
| 深层 MLP | 100% |

同时把挑战目标从 90% 提高到 95%，让线性模型和 MLP 的差距更明显。

**我的判断：**

保留该修正，因为修正后的数据更符合“非线性分类”的教学目标，同时仍能展示线性模型的能力边界。

### 3.6 可视化问题与修正

**问题一：热力图只显示左上角**

原因：离屏 Canvas 默认尺寸为 300 × 150，但只写入了 84 × 84 的像素数据，随后整张画布被缩放到显示区域。

修正：显式设置离屏 Canvas 的宽高为 84 × 84。

**问题二：决策边界呈明显锯齿**

原因：最初按网格单元直接画边界线段，分辨率不足。

修正：改为 marching squares，根据相邻格点的概率值线性插值，生成平滑等高线。

**问题三：中文显示为问号**

原因：通过 PowerShell 管道向补丁工具传递中文时，默认编码不是 UTF-8，导致中文字符被替换为 `?`。

修正：将管道输出编码显式设置为 UTF-8，重写受影响文件，并用 Python 检查 UTF-8 和关键中文文本。

### 3.8 从“演示页”升级为 10 关引导

**我的判断：** 原来的页面功能完整，但对非专业用户来说缺少学习路径，看起来像一个课后作业。希望把知识点拆成可以自动判定的关卡，让完全不懂神经网络的人跟着点击就能学完一套内容。

**AI 给出的方案：**

- 新增 `js/levels.js`，每个关卡包含问题引入、自动配置、操作步骤、过关条件、本关结论。
- 关卡条件分为状态判定、历史判定和理解判定三类。
- 引导卡放在侧栏顶部，自动高亮下一步控件，主操作按钮直接放在卡片里。
- 进度保存到 `localStorage`，支持关卡地图和重置。
- 增加“错误标签（训练集）”控制，用可控的数据污染演示数据质量对模型上限的影响。

**实现中修正过的问题：**

- 最初想用“160 个样本训练深层网络”演示过拟合，实测训练集和测试集差距不稳定，放弃该方案。
- 尝试增加宽型 MLP 强制记忆错误标签，训练 1200 轮耗时约 129 秒且仍未复现，删除该预设。
- 最终改为“30% 训练标签翻转”的数据质量关卡：错误标签存在时测试准确率约 78%，清零后回到 100%，结果稳定可复现。
- 关卡地图被 CSS 的 `display: grid` 覆盖了 `hidden` 属性，导致默认展开；增加 `.tutor-map[hidden] { display: none; }` 修复。
- 手机端顶栏品牌文字换行，隐藏副标题和“实验说明”链接，并禁止品牌文字收缩。

## 4. 我采纳与拒绝的方案

### 采纳

- 采用零依赖静态网页，不引入 TensorFlow.js 或后端。
- 采用从零实现的 MLP，突出课程知识点。
- 增加一键演示，降低非专业用户使用门槛。
- 使用 Canvas 自绘曲线和决策边界，避免额外图表库。
- 增加 JSON 导出和截图导出。
- 增加 10 关引导式学习路径，把“能玩”升级为“能学”。
- 增加错误标签控制，用真实存在的数据问题讲模型上限。

### 拒绝

- 不做普通聊天机器人：依赖 API Key，且容易被认为只是套壳。
- 不使用 Flask/Streamlit：GitHub Pages 无法运行 Python 后端。
- 不加载远程预训练模型：演示时可能受网络影响。
- 不把学习率和训练轮数放在首屏：会吓退非专业用户。
